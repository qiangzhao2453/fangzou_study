火山方舟 Managed Agents

不用搭服务器、不用写复杂代码，像发微信一样给云端数字助手派任务。
这份教程用大白话带你从零开始，搞懂概念 → 跑通流程 → 避开常见坑。

一、入门概念：先搞懂这 5 个词

下面的概念是使用 Managed Agents 的基石，花 5 分钟看一遍，后面操作就顺了。

🧩 Agent（智能体）—— 你给助手定的人设

把 Agent 理解为一份"招聘启事 + 员工手册"。它规定了：助手叫什么、性格和能力范围是什么（系统提示词）、能调用哪些工具（查网页、读写文件、运行代码）、有没有特殊技能（Skills）或外部系统接口（MCP）。

重点 Agent 本身不干活，它只是一份"模板"。你可以把同一个 Agent 用在很多个任务里。
避坑 不要把一次性任务写进 Agent 的系统提示词。系统提示词只写长期稳定的规则，具体任务在 Session 里发。

🏢 Environment（环境）—— 助手干活的办公室

Agent 要工作，总得有个办公桌、电脑和软件吧？Environment 就是给 Agent 准备的云端办公室。你可以指定：预装哪些软件（Python、Node.js等）、能不能连外网、以及一些常用配置。

重点 同一个 Environment 可以被很多 Session 共用，但每个 Session 都有自己独立的"文件抽屉"，彼此不串门。
避坑 Environment 的名字在同一个项目里必须唯一，重复会报错。建议用有意义的命名，比如"数据分析环境-生产"。

📋 Session（会话）—— 一次具体的任务

如果说 Agent 是员工手册，Environment 是办公室，那 Session 就是一次具体的"工作项目"。创建 Session 就是告诉平台："请让这位员工（Agent），在这个办公室（Environment）里，帮我完成这个任务。"

重点 Session 创建后不会自动开始工作，你必须主动发第一条消息，它才会从"待机"变成"运行中"。
避坑 一个 Session 长时间不用（默认30天），其沙箱会被清理，但聊天记录和事件历史会永久保留。

💬 Event（事件）—— 你们之间的聊天记录

你和 Agent 之间所有的互动，本质上都是在交换 Event（事件）。包括你发消息、Agent回复、它调用工具、状态变化、错误提示等，都按时间顺序保存在服务端，像聊天记录一样随时回看。

重点 所有事件自动保存，你不需要自己维护对话历史。
避坑 绝大多数情况下，一次请求只能发一个事件。只有在发 user.message 时可以紧跟一个 system.message 作为临时补充，且必须放最后。

🔧 Tools / Skills / MCP —— 助手的三板斧

这三个词都是给 Agent"加能力"的，但用法不同：

能力大白话解释什么时候用
Tools系统自带的工具箱，比如读写文件、运行命令、联网搜索只要让 Agent 在云端"动手"干活，基本都要开
Skills可复用的技能包，封装了某个领域的知识和流程有固定流程、团队规范、内部手册时优先用
MCP连接外部系统的接口，比如 GitHub、Slack、Notion需要操作已有外部系统时用
重点 Tools 是"手"，Skills 是"脑中的知识库"，MCP 是"通往外面世界的门"。
避坑 MCP 涉及外部系统权限，默认需要人工确认才能执行。不要盲目改成自动放行。

二、基础操作：四步跑通你的第一个 Agent

下面按照实际操作的顺序，一步步带你走完。每步都可以点击展开查看详情。

0
开账号、拿钥匙
注册登录 → 创建 API Key → 开通服务

正式动手前，你需要完成三件准备工作：

1. 注册/登录火山方舟控制台，找到 Managed Agents 模块；

2. 创建 API Key：这相当于调用服务的"密码"，后续代码里会用到；

3. 开通 Managed Agents 服务和模型服务：就像买手机要先开套餐一样。

重点 API Key 是敏感信息，不要直接写在代码里。建议配置成环境变量 ARK_API_KEY。
避坑 API Key 一旦泄露，别人可能用你的额度跑任务，一定要保管好。Windows 用 setx，Mac/Linux 用 export 设置环境变量。
1
创建 Agent（给助手写招聘启事）
控制台 → Managed Agents → Agents → 创建

操作路径：进入控制台 → Managed Agents → Agents → 创建 Agent。

需要填写的内容：

• 名称：中英文+数字，1~64 个字符

• 模型：选择大模型作为"大脑"，如 doubao-seed-2-1-pro-260628

• 系统提示词：用自然语言写清楚它是谁、怎么说话、遵守什么规则

• Tools：勾选要给的工具，新手建议先开 agent_toolset_20260701

• Skills / MCP / Multi Agent：新手可先跳过

保存后系统返回一个 agent_id，复制下来备用。

重点 系统提示词写得好不好，直接决定 Agent 的表现。建议用"角色 + 任务边界 + 输出风格"三段式写法。

示例："你是一位耐心的数据分析助手。你的任务是根据用户上传的销售数据，找出异常点并给出改进建议。输出时请用中文，分点说明，避免使用专业术语。"
避坑 不要在系统提示词里写太长的操作手册（会挤占上下文空间）。修改 Agent 配置时必须带上当前版本号，否则更新失败。skills 字段是新数组整体覆盖旧数组，不是追加。
2
创建 Environment（给助手配办公室）
控制台 → Managed Agents → Environments → 创建

操作路径：控制台 → Managed Agents → Environments → 创建 Environment。

• 类型：目前只支持"云托管"

• 预装包：如需要 Python 的 pandas、numpy 等，就在这里加

• 环境变量：比如设置时区 TZ=Asia/Shanghai

• 网络：一般选允许出站网络访问

保存后系统返回 environment_id，复制下来备用。

重点 预装包在沙箱启动时自动安装，同一 Environment 的多个 Session 会缓存这些包，不用重复下载。
避坑 Environment 名字也要唯一。依赖版本建议锁定（如 pandas==2.2.0），避免日后自动升级到不兼容版本。需要访问特定网站的话，在网络设置里放行对应域名。
3
创建 Session（正式开工）
控制台 → Sessions → 创建 → 选择 Agent 和 Environment

操作路径：控制台 → Sessions → 创建 Session。

选择：刚才创建的 Agent、刚才创建的 Environment、给任务起个标题（可选）。

保存后系统返回 session_id，复制下来。

重点 此时 Session 的状态是 idle（待机），Agent 还没开始干活。你需要再发一条消息，它才会进入 running（运行中）。
避坑 如果 Agent 需要访问外部系统（如 GitHub），创建 Session 时要挂上对应的 Vault（凭据库）。每个 Session 独立，文件和状态不会互相影响。
4
发消息、看反馈、拿结果
在 Session 会话面板输入任务 → 查看事件时间轴

在 Session 详情页的会话面板里输入任务，比如：

用 Python 生成前 20 个斐波那契数，并保存到 fibonacci.txt。

点击发送后，Agent 会开始工作。你可以在事件时间轴（Trace）里看到它的一举一动：

它在思考 → 调用 write 工具写代码 → 调用 bash 运行代码 → 调用 read 查看结果 → 回复你结果 → 进入 idle 状态。

重点 如果用代码接入，要先打开 SSE 事件流（实时推送）再发消息，顺序颠倒会漏掉事件。事件流会推送 agent.message、agent.tool_use、session.status_idle 等事件。
避坑 工具权限策略设为"每次确认"时，Agent 调用工具前会暂停等批准。运行中可随时发 user.interrupt 中断它。上传文件可以通过附件、文件链接或文件 ID 三种方式。

三、常见问题：新手最容易踩的 10 个坑

点击问题展开答案，每个都附带了重点和避坑提示。

创建 Session 只是"搭好舞台"，发消息才是"按开始键"。这是故意设计成这样的，方便你先检查环境、注入凭据，再正式启动任务。

重点 创建 Session → 发 user.message → Agent 开始运行，这是固定流程。

绝对不要直接写在代码里。推荐放在环境变量里：

• Mac/Linux：

export ARK_API_KEY="your_api_key_here"

• Windows CMD：

setx ARK_API_KEY "your_api_key_here"

• Windows PowerShell：

$env:ARK_API_KEY = "your_api_key_here"

避坑 setx 设置的环境变量需要重新打开终端窗口才生效。

Agent 是"员工手册"，Session 是"一次实际工作"。

• 同一本手册可以招很多个项目组（多个 Session）

• 每个项目组有自己的聊天记录和文件，互不干扰

• 修改手册后，新项目组按新版执行，老项目组不受影响

重点 想换 Agent 能力，先改 Agent 配置，再新建 Session 测试。

Environment 是"办公室模板"，Session 是"实际使用的一间办公室"。

• 同一间办公室模板可以复制出很多间独立办公室

• 每间办公室里的文件和状态彼此隔离

• 同一 Environment 的多个 Session 会共享预装包的缓存，启动更快

重点 Environment 不保存任何 Session 的文件，它只是配置模板。

两种常用方式：

1. 通过 Files API 上传：本地文件传到平台，拿到 file_id，在创建 Session 或发消息时引用它。

2. 通过 TOS 对象存储挂载：文件放在火山对象存储里，在 Session 中按目录挂载。

上传后文件以只读形式挂载到沙箱的 /mnt/session/uploads/ 目录。

避坑 单个 Session 最多挂载 100 个文件。挂载的文件是只读副本，Agent 不能直接修改原文件。上传 Files API 时要设置 purpose=agent。

Vaults 是"凭据保管库"。当 Agent 需访问外部系统（GitHub、Slack、Notion 等）时，把密钥存进 Vaults，创建 Session 时挂上去。这样密钥不会暴露给沙箱内的进程，更安全；同一 Agent 可代表不同用户操作不同账号。

重点 Vaults 在 Session 级别使用，不在 Agent 级别使用。
避坑 不要把用户 token 直接写进 Agent 定义里。环境变量类型的凭据只适用于"把密钥原样塞进请求头"的场景。

控制 Agent 调用工具前是否要先问你：

• always_allow：直接执行，不需要确认（适合低风险、只读工具）

• always_ask：暂停，弹出确认请求，你点允许后才继续（适合高风险操作）

默认内置工具集是 always_allow，MCP 工具集是 always_ask。

避坑 即使对某个 MCP Server 开了 always_allow，以后新增的工具也会自动放行，务必确认可信。

Skills 是"可复用的技能包"。比如团队有固定的会议纪要模板、代码规范、数据分析流程，都可以打包成 Skill 让 Agent 直接调用。

上传方式：逐个文件上传（Multipart）或上传 Zip 压缩包。Skill 包里必须包含 SKILL.md 说明书。

避坑 Zip 包不超过 50MB，单个版本最多 500 个文件。单个 Agent 最多挂载 20 个 Skills。更新 skills 字段时新数组整体覆盖旧数组，注意保留需要的 Skill。

Multi Agent 就是"让多个 Agent 组队干活"。比如一个总负责人 Agent 接到任务后，把子任务分别派给"代码审查员"、"测试工程师"、"文档工程师"，最后自己汇总结果。

重点 新手入门阶段不需要用 Multi Agent。先把单个 Agent 玩熟，再考虑多 Agent 协作。
避坑 目前只支持一层委派（协调器→子智能体，子智能体不能再继续往下派）。配置了 Multi Agent 的 Agent 不能再被其他 Agent 当作子智能体。每个子线程独立计费，注意控制成本。

先看事件流里的错误事件，常见情况：

现象可能原因怎么办
状态变成 terminated不可恢复的错误查看 session.error 事件内容
模型返回失败模型限流或暂时不可用等一会重试，或换模型
MCP 连接失败凭据错、网络不通、Server挂了检查 Vault 配置和网络白名单
工具调用失败命令写错、文件不存在、权限不足看工具结果里的错误信息
回复质量差系统提示词太模糊优化系统提示词，增加示例
避坑 Session 在 running 状态时不能直接删除，要先发中断事件让它回到 idle。删除 Session 会永久清空沙箱和事件记录，操作不可逆。

附：快速自查清单

在开始你的第一个任务前，逐项核对。点击即可勾选。

  • 已开通 Managed Agents 服务
  • 已开通模型服务
  • 已创建 API Key 并配置为环境变量
  • 已创建 Agent，并复制了 agent_id
  • 已创建 Environment，并复制了 environment_id
  • 已创建 Session，并发送了第一条 user.message
  • 已打开事件流查看实时反馈
  • 如涉及外部系统，已创建 Vault 并在 Session 中挂载

Managed Agents 的核心理念是"把通用基础设施交给平台，你只专注业务逻辑"。

刚开始不要怕试错，先在控制台里点点按钮、跑几个简单任务，流程跑通了再考虑写代码接入。祝你早日养出一个得心应手的数字助手！
